# CRM v1 для отдела продаж TSK

Проект: `crm.podolsky.build`  
Назначение: рабочая CRM для клиентских лидов ремонта и отделки.  
Статус: архитектурное ТЗ и макет для согласования перед разработкой.

## 1. Цель v1

Сделать не прототип и не лендинг, а закрытую рабочую систему с общей базой, ролями, доступами, задачами и управлением лидами.

CRM v1 должна отвечать на вопросы:

- сколько лидов в работе;
- кто ответственный;
- какой следующий шаг;
- где просрочено касание;
- какие источники дают заявки;
- что дошло до замера, КП, договора и предоплаты;
- какие лиды требуют подключения Игоря;
- кто и что менял в карточках.

HR-кандидаты в v1 не входят.

## 2. Техническая модель

Рекомендуемый контур:

- домен: `crm.podolsky.build`;
- приложение: отдельный backend + frontend, не GitHub Pages;
- backend: Node.js;
- база: PostgreSQL;
- ORM: Prisma;
- авторизация: логин / пароль, серверные сессии;
- пароли: только хэш;
- файлы v1: ссылки на Google Drive / Яндекс Диск / другое облако;
- деплой: отдельное приложение рядом с боевым табелем или на отдельном VPS/PaaS.

Почему не GitHub Pages: CRM хранит клиентские данные, роли, права, историю действий и общую базу. Статическая страница для этого не подходит.

## 3. Роли

### Админ / владелец

Видит все лиды, пользователей, источники, бюджеты, КП, отчеты и журнал действий.

Может:

- создавать, редактировать и архивировать лиды;
- менять ответственных;
- управлять пользователями;
- менять роли;
- управлять статусами, источниками, причинами отказа;
- экспортировать базу;
- смотреть журнал действий;
- менять настройки CRM.

### Руководитель продаж

Видит все лиды отдела, менеджеров, бюджеты, КП и отчеты.

Может:

- редактировать лиды;
- менять ответственных;
- контролировать статусы;
- архивировать лиды;
- смотреть эффективность менеджеров и источников.

Ограничение: не меняет системные настройки. Экспорт лидов только по разрешению админа.

### Менеджер

Видит:

- свои лиды;
- общую очередь новых лидов без ответственного.

Может:

- создавать лиды;
- брать новый лид в работу;
- редактировать свои лиды;
- менять статус по своим лидам;
- ставить задачи;
- вести касания;
- ставить флаг "нужен Игорь".

Не может:

- видеть чужие лиды;
- видеть чужую историю касаний;
- удалять лиды;
- экспортировать всю базу;
- менять настройки CRM.

### Ассистент продаж

Видит общую очередь, свои внесенные лиды и источники.

Может:

- создавать лиды;
- фиксировать источник;
- вносить первичные данные;
- вести первичную квалификацию;
- ставить задачи менеджерам.

Ограничения:

- деньги видит ограниченно или не видит;
- удаление запрещено;
- экспорт запрещен;
- настройки запрещены.

### Сметчик

Видит лиды после замера, на смете и КП.

Может:

- смотреть объект, площадь, тип работ, фото и вводные;
- добавлять ссылку на смету / КП;
- менять статус сметы.

Не видит всю базу продаж, не меняет ответственных и не экспортирует данные.

### Просмотр

Видит только разрешенные разделы. Не редактирует, не удаляет, не экспортирует.

## 4. Воронка v1

Статусы:

1. Новый лид
2. Первичный контакт
3. Квалификация
4. В прогреве
5. Назначен замер
6. Замер проведен
7. Готовится КП / смета
8. КП отправлено
9. Дожим
10. Договор
11. Предоплата
12. Взято в работу
13. Отказ
14. Архив

Правила:

- активный лид не может быть без источника;
- активный лид не может быть без следующего действия;
- отказ невозможен без причины отказа;
- физического удаления нет, только архив;
- переход в "Предоплата" и "Взято в работу" должен быть виден руководителю / админу;
- после "КП отправлено" автоматически создается задача "Дожим после КП";
- после "Замер проведен" создается задача "Передать на смету";
- лиды с флагом "нужен Игорь" выводятся отдельно.

## 6. Задачи и контроль

Типы задач:

- позвонить;
- написать в Telegram / WhatsApp;
- уточнить вводные;
- назначить замер;
- провести замер;
- передать на смету;
- отправить КП;
- дожать после КП;
- проверить договор;
- проверить предоплату;
- передать в производство.

Блок "Что требует внимания" на главном экране:

- просроченные касания;
- замеры сегодня;
- КП не отправлено после замера;
- дожим после КП;
- договор без предоплаты;
- задачи без ответственного;
- новые лиды без ответственного;
- лиды, где требуется Игорь.

В v1 уведомления только внутри CRM: подсветка, фильтры, счетчики. Telegram/email - v2.

### Таблица лидов

Реестр с фильтрами:

- статус;
- ответственный;
- источник;
- дата следующего контакта;
- просрочено;
- бюджет;
- нужен Игорь;

### Карточка лида

Центральный рабочий экран: данные клиента, объект, статус, следующий шаг, история касаний, задачи, ссылки на файлы, флаг подключения руководителя.

### Источники

Список источников и базовый отчет:

- сколько лидов пришло;

### Отчеты

Минимум v1:

- конверсия по воронке;
- просроченные задачи;
- эффективность менеджеров;
- замеры назначены / проведены;

- договоры;

### Админка

Разделы:

- пользователи;
- роли;

- статусы;
- причины отказов;
- типы объектов;
- типы работ;

- журнал действий.

## 8. Сущности базы

Минимальные таблицы:

- users;
- roles;
- permissions;
- leads;
- lead_sources;
- lead_statuses;
- contacts;
- activities;
- tasks;
- files;
- estimates;
- comments;
- loss_reasons;
- audit_log;
- import_batches.

Ключевая логика доступа:

- у лида есть `owner_id`;
- у лида есть `created_by`;
- новый лид может быть без `owner_id`, тогда он в общей очереди;
- менеджер видит `owner_id = current_user.id` и `owner_id is null`;
- руководитель продаж видит лиды отдела;
- админ видит все;
- сметчик видит лиды только в разрешенных статусах;
- все важные изменения пишутся в `audit_log`.

- `client_leads_import.xlsx` / CSV;

Импорт должен:

- показать предварительный просмотр;

- позволить откатить импорт администратору;
- не смешивать HR-кандидатов и клиентские лиды.

| Этап | Ответственный | Обязательное действие | Обязательные поля | Автозадача | Просрочка |
|---|---|---|---|---|---|
| Источник / новый лид | Ассистент / менеджер | Внести лид и источник | источник, контакт, статус | связаться с клиентом | нет контакта в срок |
| Первичный контакт | Менеджер / ассистент | Позвонить или написать | контакт, результат касания, следующий шаг | уточнить вводные | нет результата касания |
| Квалификация | Менеджер | Проверить объект, бюджет, сроки, проект | объект, тип работ, район, бюджет или пометка "не назван" | решить целевой / нецелевой | нет решения по квалификации |
| В прогреве | Менеджер | Назначить дату следующего касания | следующий шаг, дата контакта | повторное касание | дата контакта прошла |
| Назначен замер | Менеджер | Согласовать дату, адрес, ответственного | дата замера, адрес / район | провести замер | дата замера прошла без результата |
| Замер проведен | Замерщик / менеджер | Внести результат замера | результат, фото/ссылка, комментарий | передать на смету | нет задачи на КП |
| Готовится КП / смета | Сметчик / Игорь | Подготовить КП | сумма КП или статус подготовки | отправить КП | срок КП прошел |
| КП отправлено | Менеджер | Зафиксировать отправку и дату дожима | дата отправки КП, сумма КП, следующий шаг | дожим через 1 день | дата дожима прошла |

| Предоплата | Руководитель / админ | Зафиксировать оплату | сумма, дата, комментарий | передать в работу | нет передачи в работу |
| Взято в работу | Руководитель / производство | Передать объект в производство | ответственный производства, комментарий | закрыть продажу | нет |
| Отказ | Менеджер / руководитель | Указать причину и комментарий | причина отказа | нет | отказ без причины запрещен |
| Архив | Админ / руководитель | Закрыть нецелевой / дубль / старый лид | причина архива | нет | нет |

## 14. Ограничения переходов статусов

Система должна запрещать бессмысленные переходы, чтобы воронка не превращалась в произвольные метки.

Минимальные правила:

- из "Новый лид" можно перейти только в "Первичный контакт", "Квалификация", "Отказ" или "Архив";
- из "Квалификация" нельзя перейти в "КП отправлено" без статусов замера / подготовки КП;
- в "Назначен замер" нельзя перейти без даты замера;
- в "Замер проведен" нельзя перейти без результата замера;
- в "КП отправлено" нельзя перейти без суммы КП или ссылки/пометки по КП;
- в "Договор" нельзя перейти без суммы сделки / условий;
- в "Предоплата" нельзя перейти без суммы и даты оплаты;
- в "Отказ" нельзя перейти без причины отказа;
- активный лид нельзя сохранить без следующего шага и даты следующего контакта;
- архивирование доступно админу и руководителю, менеджеру только по разрешенному сценарию или через запрос.

## 16. Поля задачи

У каждой задачи должны быть:

- ID;
- связанный лид;
- тип задачи;
- ответственный;
- срок;
- статус: новая / в работе / выполнена / просрочена / отменена;
- результат;
- дата создания;
- кто создал;
- дата закрытия.

Автоматические задачи:

- новый лид создан -> связаться с клиентом;
- замер проведен -> подготовить КП;
- КП отправлено -> дожим через 1 день;
- договор -> проверить подписание / предоплату;
- дата контакта прошла -> подсветить просрочку.

Ручные задачи:

- повторно написать;
- отправить портфолио;
- уточнить бюджет;
- согласовать дату;
- отправить договор;
- перенести контакт.

## 17. Источники как рабочая база

Источник - не просто текстовое поле в лиде. Это отдельная сущность.

Поля источника:

- название;
- ссылка;
- тип: ЖК / район / дизайнер / риелтор / Авито / Профи / рекомендация / Telegram / другое;
- кто нашел;
- можно ли размещаться;
- статус источника;
- комментарий;
- дата создания;
- кто создал.

Отчетные поля считаются из лидов:

- сколько лидов дал;
- сколько квалифицировано;
- сколько назначено замеров;
- сколько замеров проведено;
- сколько КП отправлено;
- сколько договоров;
- сколько взято в работу;
- конверсия по этапам.

## 18. Формулы отчетов v1

| Отчет | Считается из | Кто видит | Фильтры |
|---|---|---|---|
| Новые лиды за период | `leads.created_at` | админ, руководитель, менеджер по своим | период, источник, ответственный |
| Лиды без ответственного | `owner_id is null` | админ, руководитель, менеджер | источник, дата |
| Просроченные задачи | `tasks.due_at < now`, статус не выполнен | по правам видимости лида | ответственный, тип задачи |
| Замеры сегодня | `leads.measurement_at = today` | админ, руководитель, ответственный | менеджер, источник |
| КП в работе | статус "Готовится КП / смета" | админ, руководитель, сметчик | сметчик, срок |
| КП отправлено | статус / `proposal_sent_at` | админ, руководитель, ответственный | период, менеджер |
| Сделки без следующего шага | активный лид без будущей задачи | админ, руководитель, ответственный | статус, менеджер |
| Лиды по источникам | `lead.source_id` | админ, руководитель | период, тип источника |
| Конверсия по статусам | переходы и текущие статусы | админ, руководитель | период, источник, менеджер |
| Эффективность менеджеров | лиды, задачи, замеры, КП, договоры | админ, руководитель | период, менеджер |
| Причины отказов | `loss_reason_id` | админ, руководитель | период, источник |
| Потенциальная сумма сделок | суммы активных КП / бюджетов | админ, руководитель | статус, менеджер |

## 19. Импорт CSV / Excel

Обязательные колонки импорта клиентских лидов:

- клиент;
- телефон;
- Telegram;
- WhatsApp;
- источник;
- статус;
- объект;
- район / адрес;
- бюджет;
- ответственный;
- следующий шаг;
- дата следующего контакта;
- комментарий;
- история касаний.

Правила импорта:

- дубль определяется по телефону, Telegram или WhatsApp;
- лид без ответственного попадает в общую очередь;
- лид без источника не импортируется как активный, а попадает в список ошибок импорта;
- неизвестный источник можно создать из импорта только админу / руководителю;
- импорт источников выполняется отдельным файлом;
- каждая загрузка получает `import_batch_id`;
- админ должен видеть результат: создано, обновлено, пропущено, ошибки, дубли;
- откат импорта доступен админу до ручных изменений карточек.

## 20. Журнал действий

Логировать обязательно:

- вход пользователя;
- создание лида;
- изменение статуса;
- смену ответственного;
- изменение бюджета / суммы КП;
- добавление комментария;
- добавление касания;
- создание и закрытие задачи;
- добавление ссылки на файл;
- архивирование;
- экспорт;
- изменение роли;
- блокировку пользователя;
- изменение системных справочников.

Запись журнала:

- дата и время;
- пользователь;
- действие;
- сущность;
- старое значение;
- новое значение;
- IP / технический идентификатор сессии, если доступно.

История действий не удаляется обычными пользователями.

## 21. Безопасность

Минимум v1:

- закрытая авторизация;
- пароли только в хэше;
- роли и права проверяются на сервере;
- клиентские данные не публичны;
- экспорт ограничен;
- менеджер не может унести всю базу;
- удаление заменено архивом;
- журнал действий обязателен;
- доступы не хранить в коде;
- резервные копии базы;
- сессии можно принудительно закрывать при блокировке пользователя.

## 22. Файлы и сметы v1

Файлы физически лежат в Google Drive / Яндекс Диск / другом облаке.

CRM хранит карточки файлов:

- тип файла: КП / смета / фото / договор / другое;
- название;
- ссылка;
- кто добавил;
- дата добавления;
- комментарий;
- связанный лид.

Загрузку файлов внутрь CRM вынести в v2.

## 23. Критерии приемки v1

CRM v1 считается готовой только если проходят проверки:

- лид без источника не создается;
- активный лид без следующего шага не сохраняется;
- отказ без причины не сохраняется;
- менеджер не видит чужие лиды;
- менеджер видит свои лиды и общую очередь новых;
- ассистент не видит деньги и не экспортирует базу;
- сметчик видит только лиды после замера / на КП;
- экспорт всей базы доступен только админу;
- просроченные задачи подсвечиваются;
- после "КП отправлено" создается задача "Дожим после КП";
- после "Замер проведен" создается задача "Подготовить КП";
- история касаний сохраняется;
- архивирование не удаляет данные физически;
- руководитель видит все лиды отдела;
- новый лид без ответственного попадает в общую очередь;
- изменение статуса, ответственного, бюджета и экспорт пишутся в журнал;
- импорт подсвечивает дубли и ошибки обязательных полей;
- CRM работает без публичного доступа к клиентской базе.
